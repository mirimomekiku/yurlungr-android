Yurlungr 0.0.4 turns the phone into a fuller development environment: 42 optional runtime packs, a JDK switcher, one-tap Run with an in-app preview, project setup that installs what a project needs, and redesigned project screens.

This release also includes the hardening changes documented in [0.0.3](https://github.com/mirimomekiku/yurlungr-android/blob/0.0.4/docs/releases/0.0.3.md).
When upgrading from 0.0.2, update **both phones** before using two-phone sharing: the authenticated,
encrypted pairing protocol is incompatible with 0.0.2 and older.

### Development environment

- **42 optional packs**, each with its own Install button, log and version checks:
  - JavaScript runtimes (pnpm, Yarn, Bun, Deno), Java & Kotlin, PHP, Dart, .NET, Databases, Swift, Zig, Elixir, Lua;
  - Crystal, Nim, Haskell, Scala, D, Perl, Shell & terminal, CLI tools, Servers & tunnels, DevOps, Media & docs, Local AI, Linux distros;
  - Native libraries, Python data & science, Debugging, Language servers, Networking, Security & signing, Data tools, Task runners, Docs & static sites, Archives, OCR & PDF;
  - a headless Chromium.
- **Settings → Development environment**:
  - choose the default JDK (17, 21, 25) or the newest, and install any version;
  - see which JDKs Gradle finds, and the environment every process gets, with copyable exports;
  - see each pack's size, with **Remove**;
  - clear caches (Gradle, npm, pnpm, Bun, pip, uv, Cargo, Go, Maven, downloaded packages);
  - update packages.
- **The same environment everywhere:** agents, terminals, setups and web runs get `JAVA_HOME`, the per-user tool folders on PATH (`~/.local/bin`, `~/.cargo/bin`, `~/go/bin`…), `PNPM_HOME`, `GOPATH`, `CARGO_HOME` and `DOTNET_ROOT`. Projects that pin a JDK (`jvmToolchain(17)`) find it.
- **JDK 21** is now what the Android SDK and Java setups install, because Termux's Gradle, Kotlin, Maven, d8 and apksigner need it.
- **System checks** shows the default JDK and pending package updates. The agents setup no longer fails on optional agents that aren't installed.

### Projects

- **Setup:** detects each stack and the runtimes it needs (marked installed or missing), and installs them before the dependencies:
  - package managers: Bun, pnpm, Yarn 2+, uv, Poetry;
  - new stacks: Deno, Elixir, Zig, .NET, Crystal, Nim, Lua;
  - native npm add-ons get the compiler and the libraries they link;
  - opt-in automatic setup when you open a project.
- **One-tap Run:** starts with the last settings, installs what's missing, picks a free port, and opens the app in the new in-app **Preview**. Start commands cover Vite (even behind `tsc && vite`), SvelteKit, Next.js, Astro, Nuxt, Angular, Create React App and Expo web, plus custom commands. Long-press Run for its options.
- **Launch profiles:** choose Framework CLI, Project script or Custom command, with Node requirements,
  configurable readiness path and startup timeout. One-tap Run restores these settings. Parcel, Webpack
  Dev Server and generic development/start scripts are also detected; npm, pnpm, Yarn and Bun are supported.
- **Next.js on Android:** Webpack compatibility is the default, with a matching SWC WASM fallback and
  an explicit compiler repair action. Missing Lightning CSS Android bindings (Tailwind/PostCSS) get an
  exact-version official WASM fallback in app cache, without rewriting project source or package files.
  Turbopack scripts show a specific recovery action.
- **Run state:** new attempts stay disabled through preparation, installation, compilation and cleanup;
  the action becomes Open when running. The browser/preview waits for the initial route to compile
  successfully (HTTP 200–399), with public-origin headers and HMR forwarded through the owned listener.
- **Preview:**
  - reload, back and forward within the app;
  - phone or desktop layout;
  - the page's console and errors;
  - open in the browser.
- **Scripts:** one-tap package.json scripts, deno tasks, composer scripts, make targets, just recipes, and Gradle, Cargo, Go, pytest, mix and .NET commands.
- **Search in files** (ripgrep), from the Files tab.
- **Agent settings** per project:
  - the agent Chat starts with;
  - instruction files (AGENTS.md, CLAUDE.md, GEMINI.md, QWEN.md), with one tap to point them all at AGENTS.md;
  - MCP servers (`.mcp.json`, optionally copied to Gemini's and Qwen's settings).
- **Redesigned tabs and dock:**
  - **Changes:** a sync card; Conflicts, Staged and Changes groups; stage and unstage; confirmed discard; a pinned commit box.
  - **Files:** a segmented filter, a summary by kind, indent guides, file-type icons and status letters.
  - **History:** search, a filter sheet, author avatars, day counts and a clearer commit sheet.
  - **Dock:** Chat, the main action and **More**. The server card is new too.
- The stat tiles and tabs hide while you scroll down. The Changes badge no longer clips.

### Daily workflow

- **Search everything:** screens, projects, recent files, chats, and the last project's scripts and files. Long-press ☰ / ‹ to open it.
- **Checks tab:** run a project's compile/lint checks and tests, then see problems by file and test failures with their messages; tap to open at the line, or **Fix with agent**.
- **Editor:** opens at a line from search, problems and failures; **Find definition** (a project search for likely definitions); **Blame**.

### Polish

- Quick Settings tiles (Dev servers, Terminal) and a home-screen widget (New chat, last project, Servers).
- **Share to Yurlungr** from other apps: ask an agent about text, links or files, or save files to a project.
- Wide screens show a project and the file it opened side by side.
- Accessibility: headings, tab states, spoken Git statuses and dock states.

### Editing, agents and comfort

- **Language servers** in the editor: problems in the gutter and a list, precise Find definition, Show info, and Complete.
- **Tabs** that keep unsaved edits, a **merge view** for conflicts (ours / base / theirs), **snippets**, and **new files from templates**.
- **SQLite browser:** tables, rows, schema and SQL (read-only unless allowed).
- **Checkpoints** for every agent prompt, with a diff and **Restore to before**. They're kept outside the project's git.
- **Usage** per chat and project: prompts, time and files changed, plus the context and cost agents report.
- **Accent colours** and **pure black**, **vibration and sounds**, **battery and heat warnings** before long jobs, **launcher shortcuts**, and a first-run **tour** with a sample project.

### Verification

- **Self-test** (Development environment): quick checks of the environment, every installed tool, git, search and notifications. **Full** also installs two small packs, switches the JDK and back, and runs a Vite app.
- On-device feature checks for the runtime (no screen interaction), run with the instrumentation runner (see DEVELOPMENT).

### New screens and notifications

- **Servers** (sidebar):
  - the web apps the app runs, with Preview, Logs and Stop;
  - listening development ports, found by probing the usual ones, because Android doesn't let apps list ports;
  - the runtime's processes, with Stop or Force kill.
- **"Finished" notifications** for terminal commands that ran 20 seconds or more (builds, installs, tests). Tap one to open that terminal. Scripts and agents can send their own with `yurlungr-notify "Title" "details"`. While the app is open these show as a toast.
- The **Markdown viewer** renders GitHub-flavoured Markdown, including README HTML, and has find, an outline, anchors, text size and live reload.
- New terminals open with a status card under a small wave mark.

### Fixes

- Automatic project setup no longer starts a second install while the first is still running.
- Project screens no longer read package files on the UI thread while scrolling.
- Development environment says which open chats and terminals still use the previous JDK.
- Release validation covers JVM and Node tests, Android lint, packaged native alignment and APK signatures.

### Release validation and APKs

- 195 JVM tests; Node launch-adapter and supervisor tests cover framework flags, compiler recovery,
  generated CSS redirects, readiness, SSR/HMR forwarding, port conflicts and process cleanup.
- Shell assets pass `bash -n`; the app and instrumentation APK compile with JDK 17+ and NDK r28.
- APKs are provided for arm64-v8a, armeabi-v7a, x86_64 and x86, plus a universal APK and SHA256SUMS.txt.
- The release APKs retain the 0.0.2 signing certificate. Install over the existing app to preserve data.
- Earlier arm64 runtime checks covered Vite 8.3.6, Next.js 16.4.5 (App/Pages Router, Webpack/WASM and HMR),
  Astro 7.4.7 and a Next.js 15.3.5/Tailwind 4.1.11/DaisyUI project with generated CSS. The merged 0.0.4
  build was not reinstalled or smoke-tested on a phone for this release because no device was connected.
  Other frameworks and project-specific native dependencies still need device validation.
